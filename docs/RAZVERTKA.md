# TurboFetch — сборка и запуск

## Что нужно на машине

Всё ставится **без sudo**, в пользовательскую папку:

| Что | Путь | Статус |
|---|---|---|
| Android SDK | `~/Android/Sdk` | platform-tools, platforms;android-37.0, build-tools;37.0.0 |
| NDK r27c | `~/Android/Sdk/ndk/27.2.12479018` | нужен только для сборки ffmpeg |
| Gradle | wrapper в проекте (9.9.0) | `./gradlew` |
| JDK | системный 25 | AGP 9.5.1 использует встроенный Kotlin 2.2.10 |

Проверить, что всё на месте:

```bash
export ANDROID_HOME=~/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools
adb version
```

## Сборка

```bash
cd ~/Documents/turbo-fetch
./gradlew assembleDebug          # APK: app/build/outputs/apk/debug/app-debug.apk (~34 МБ)
./gradlew testDebugUnitTest      # 25 юнит-тестов
```

Сетевые тесты (нужны YouTube и TikTok) включаются явно:

```bash
./gradlew testDebugUnitTest -Dturbofetch.network=true --tests '*SpikeTest'
```

## Установка на телефон

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

При первом подключении по USB телефон спросит «Разрешить отладку по USB?» — нужно
подтвердить. Если телефон не виден в `adb devices`, проверь, что кабель именно
data-кабель (многие только на зарядку).

Беспроводной вариант (кабель не нужен): Настройки → О телефоне → 7 раз тапнуть
«Номер сборки» → Параметры разработчика → Беспроводная отладка → Сопрячь с помощью кода.

## Как пользоваться

1. В TikTok / YouTube / X нажимаешь «Поделиться» → TurboFetch.
   Ссылку можно и вставить руками в поле сверху.
2. Задача появляется в очереди, через секунду подтягиваются название и форматы.
3. Тап по карточке — шторка: качество, качество звука, mp3, имя файла.
4. Карточки можно перетаскивать за ручку слева — это задаёт порядок пакетной скачки.
5. «Скачать» → прогресс → файл в `Movies/TurboFetch` (виден в галерее).

## Куда кладутся файлы

- видео — `Movies/TurboFetch/`
- аудио — `Music/TurboFetch/`

Имена строятся по шаблону из настроек: `{title}`, `{author}`, `{quality}`, `{ext}`,
`{date}`, `{id}`.

## Как это устроено

```
ui/          экраны и ViewModel'ы (Compose + Material 3)
domain/      модели, разбор ссылок, интерфейс DownloadEngine
data/        Room, резолверы площадок, MediaStore, склейка, ffmpeg
worker/      WorkManager: загрузка, foreground-сервис, уведомления
```

**Скачивание идёт напрямую с CDN** площадки — байты не проходят ни через какой
сервер, поэтому скорость не режется.

| Площадка | Как разбирается ссылка | Нужен JS-рантайм |
|---|---|---|
| TikTok | скрейп HTML, мобильный User-Agent | нет |
| X | `cdn.syndication.twimg.com/tweet-result` | нет |
| YouTube | NewPipeExtractor (GPL-3.0, JitPack) | нет (Rhino внутри) |

**Склейка** видео и звука — штатные `MediaExtractor` + `MediaMuxer`, без ffmpeg.
**mp3** — единственное место, где нужен ffmpeg: он собран под arm64-v8a с
libmp3lame и лежит в `jniLibs`.

## ffmpeg для mp3

Бинарники ffmpeg (22 МБ) в репозиторий не попадают — они воспроизводимы сборкой.
Чтобы получить mp3-конвертацию, выполни один раз:

```bash
./tools/build-ffmpeg.sh
```

Скрипт скачает `ffmpeg-android-maker`, соберёт ffmpeg 8.1.2 с `libmp3lame`
только под `arm64-v8a` (с выравниванием страниц 16 КБ) и положит результат в
`app/src/main/jniLibs/arm64-v8a/`. Займёт около часа.

Без этого шага приложение собирается и работает, но mp3-конвертация вернёт
ошибку — остальное не пострадает.

## Ограничения

- **YouTube без PO-токена** отдаёт полную лестницу качеств (проверено: до 2160p),
  но YouTube регулярно ломает извлечение — экстрактор приходится обновлять.
  Версия зафиксирована на 0.26.5.
- **mp3 требует arm64-v8a.** На других архитектурах приложение поставится,
  но конвертация в mp3 вернёт ошибку (обычный видеофайл скачается нормально).
- **X** использует недокументированный эндпоинт — он может исчезнуть, поэтому
  резолвер изолирован в одном классе.
- **YouTube — только MP4.** WebM/VP9 в MP4 не склеить, поэтому webm-варианты
  не показываются в списке качества.
