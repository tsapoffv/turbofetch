# TurboFetch

Android-приложение для скачивания видео **напрямую с CDN** — без прокси,
без рекламы и без поднятого сервера.

Поддерживаются YouTube, TikTok, X (Twitter), Instagram, SoundCloud и Spotify.

> Описание проекта для ресерча — [`docs/TurboFetch.pdf`](docs/TurboFetch.pdf).
> Исходное техническое задание — [`docs/ORIGINAL-BRIEF.md`](docs/ORIGINAL-BRIEF.md).

---

## Возможности

| | |
|---|---|
| **Скачивание напрямую с CDN** | Файл идёт мимо серверов сервиса, на полной скорости |
| **YouTube** | До 2160p, звук склеивается автоматически |
| **TikTok** | Разбор обеих схем разметки страницы |
| **X (Twitter)** | Разбор через syndication-эндпоинт |
| **Instagram** | Публичные посты, Reels и карусели без логина; берётся DASH-манифест |
| **SoundCloud** | Треки целиком: HLS-плейлист склеивается в m4a, mp3 — по желанию |
| **Spotify** | Метаданные трека + сам трек с YouTube (аудио с CDN) |
| **Альбомы и плейлисты** | Список треков с выбором: отметьте нужное — и они скачаются |
| **Ссылка в истории** | Скопировать исходную ссылку на скачанное в один тап |
| **mp3** | Перекодирование через ffmpeg, собранный под arm64-v8a |
| **Гифки из X** | Настоящий анимированный GIF или mp4 без звука — как в мессенджерах |
| **Очередь** | Задания с перетаскиванием, лимит параллельных загрузок |
| **Докачка** | Обрыв связи не считается ошибкой — файл продолжается с места обрыва |
| **История** | Скачанные файлы хранятся отдельно от очереди |
| **Шаблон имени файла** | Настраивается, с живым предпросмотром |
| **Автооткрытие** | Готовый файл можно открывать плеером автоматически |
| **Закрываться после «Поделиться»** | Ссылка уходит в очередь, окно приложения не открывается |

Приложение **не публикуется в магазинах** — ставится установкой APK.

## Сборка

### Что нужно

| Компонент | Версия |
|---|---|
| JDK | 17 или новее (проверено на 25) |
| Android SDK | platform **37**, build-tools **36** |
| Gradle | обёртка в репозитории, отдельно ставить не нужно |
| NDK | r27c — **только** если нужен mp3 |

Проверить, что SDK на месте:

```bash
echo $ANDROID_HOME          # должно указывать на каталог с SDK
ls $ANDROID_HOME/platforms # должен быть android-37
```

Если переменной нет, добавь в `~/.zshrc`:

```bash
export ANDROID_HOME=$HOME/Android/Sdk
export PATH=$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin
```

### Обычная сборка

```bash
./gradlew :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

### Установка и запуск

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.turbofetch.debug/com.turbofetch.MainActivity
```

Либо одной командой — есть готовый скрипт:

```bash
./tools/install.sh
```

### Сборка ffmpeg (нужна только для mp3)

Без этого шага всё работает, кроме конвертации в mp3.

```bash
./tools/build-ffmpeg.sh
```

Скрипт собирает ffmpeg 8.1.2 с libmp3lame под `arm64-v8a` с выравниванием
страниц памяти 16 КБ (требование Android 15) и кладёт бинарник в
`app/src/main/jniLibs/arm64-v8a/`. Сборка занимает около 20 минут и требует
NDK r27c.

Готовый бинарник в репозиторий **не коммитится** — он весит 22 МБ и
воспроизводится скриптом.

### Тесты

```bash
./gradlew :app:testDebugUnitTest
```

32 юнит-теста, все проходят без сети. Тесты, ходящие в интернет, включаются
явно:

```bash
./gradlew :app:testDebugUnitTest -Dturbofetch.network=true
```

### Описание проекта в PDF

```bash
~/ml/.venv/bin/python tools/make-pdf.py
```

Пересобирает `docs/TurboFetch.pdf` из данных в скрипте.

## Как это устроено

```
ui/       экраны Compose и ViewModel'ы
domain/   модель задачи, форматы, правила
data/     Room, MediaStore, резолверы площадок
worker/   фоновая загрузка через WorkManager
```

Движок отделён от интерфейса одним интерфейсом — `DownloadEngine`. Единственная
точка, где UI знает о загрузке, — он и есть.

Схема подробнее — в разделе «Архитектура» PDF-документа.

## Производительность (0.3.0)

Раньше при десятке одновременных загрузок интерфейс заметно подтормаживал.
Причина была не в самой загрузке, а в том, как прогресс доходил до экрана:

| Что было | Что стало |
|---|---|
| Событие прогресса на каждый прочитанный 64 КБ — это сотни событий в секунду | `ProgressThrottle`: событие отдаётся, когда изменился целый процент, и не чаще раза в 100 мс |
| Каждое событие писалось в SQLite: SELECT строки + UPDATE всех колонок, включая JSON со списком форматов | Прогресс живёт в памяти и доезжает до экрана отдельным потоком — в базу он не пишется вовсе |
| Любая запись в таблицу `tasks` заставляла заново читать и разбирать JSON всех задач | Задачи и прогресс — два разных потока: список перерисовывается редко, полоса — точечно |
| Строка задачи перерисовывалась целиком на каждый тик | Модели помечены `@Immutable`, ViewModel'ы — `@Stable`: неизменившиеся строки не трогаются |
| `IntrinsicSize.Min` заставлял измерять текст в строке дважды | Полоска-«затёпка» рисуется, а не занимает место в разметке |
| Полоса прогресса меняла ширину, а это перемешивало всю строку | Полоса рисуется кистью: геометрия родителя не меняется |
| В шуточной теме каждая строка очереди крутила свою бесконечную анимацию (60 кадров в секунду на строку) | Живой градиент остался у кнопок, у строк — статичный |
| Десяток задач мог одновременно запустить десяток ffmpeg | Пост-обработка (склейка, mp3, GIF) ограничена двумя слотами |
| Буфер склейки — 12 МБ на дорожку | 1 МБ с ростом под крупный сэмпл |
| Копирование в MediaStore шло буфером 8 КБ | 256 КБ: в 32 раза меньше вызовов записи |
| У всех загрузок было одно уведомление — они затирали друг друга | Свой ID уведомления на задачу |

Побочно починены две вещи: недокачанный файл при смене потока больше не
остаётся на диске (иначе к нему дописывались байты старого потока), а
брошенные загрузки больше не раздувают кэш.

Замер: 84 юнит-теста, из них 7 — на троттлинг прогресса.

## Ограничения

- Слой разбора X недолговечен: эндпоинт не документирован и может измениться.
- TikTok периодически меняет разметку — парсер придётся обновлять.
- Instagram отдаёт видео **без звука** там, где у ролика лицензионная музыка:
  площадка вырезает дорожку сама, отдельной ссылки на неё нет.
- SoundCloud отдаёт трек подписанным HLS-плейлистом: подпись живёт около
  двух часов, поэтому ссылка не кэшируется.
- Spotify отдаёт только метаданные: само аудио зашифровано (Widevine). Трек
  ищется на YouTube по названию и артисту, и если совпадение сомнительно,
  приложение скажет об этом, а не выдаст случайный ролик.
- Альбомы и плейлисты Spotify показываются списком треков с галочками: по
  умолчанию отмечены все, можно оставить нужное. Скачиваются они отдельными
  задачами — с общей пометкой, из какого альбома взят трек.
- Плейлист Spotify отдаёт только первые 50 треков: пагинации у embed-страницы
  нет, и список показывается целиком, но без продолжения.
- mp3 работает только на arm64-v8a.
- Гифка из X перекодируется через ffmpeg, поэтому на не-arm64 устройстве
  доступен только вариант «MP4 без звука». Кадры ужимаются до 480 px и
  15 кадров в секунду — иначе GIF весит десятки мегабайт.
- Установка APK в обход магазина: на устройстве нужно разрешить установку
  из неизвестных источников.
